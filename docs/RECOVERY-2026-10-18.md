# Boot handoff recovery: engineering lesson

A development install used a custom initramfs to select an Arch root nested inside Android userdata. Its selector still checked for files in the old Debian parent root before selecting Arch. Removing those Debian files left the nested Arch tree intact but prevented the handoff from reaching it.

A later initramfs change removed that specific dependency, and a long-running Arch session was observed afterward. This was a recovery of the development layout, not validation of the direct-root distro design. It did not prove cold boot, desktop startup, or a complete rollback path.

## Design lessons

- The initramfs must select and mount the Arch root directly, without relying on Debian paths or userspace.
- Root selection must be explicit, validated, and independent from user-data contents.
- The source, kernel, device tree, modules, and firmware must be version-matched and recorded.
- Verify complete boot-partition writes by readback; retain a tested recovery path before changing boot assets.
- Treat Android userdata as destructive install target storage and back it up before formatting.
- Do not confuse systemd handoff or a long uptime with a complete desktop/cold-boot acceptance test.

Exact device images, partition hashes, boot identifiers, account names, host paths, and private recovery logs are intentionally excluded from this public project note.
